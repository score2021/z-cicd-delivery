# 新建或改造交付链

## 先选择最短可用架构

为 checkout、依赖／镜像下载、构建上传、部署接口、入口验收分别记录来源→目的、协议、证书身份、认证、允许变更范围和可复现探测。不要把控制面、业务面和观测面画成一条链；发布主机故障可能只阻塞新发布，不应无证据地说业务也宕机。

| 发现 | 推荐判断 |
| --- | --- |
| 可信私网 Runner 已覆盖源站、仓库和部署目标 | 复用并约束权限，避免不必要跳板 |
| 只有共享 Runner 可拉源码，部署端只能受限进入 | 比较可信中继、短期身份、私网通道；只有必要才采用固定命令转发 |
| 镜像无法从某公共源拉取 | 验证官方镜像的可达渠道并固定平台/digest；不因为替换域名就假设内容可信 |
| 入口只允许办公网 | 为 CI 明确受控验证来源或私网验证方式，保留白名单，不临时放开全部公网 |
| 观测组件独立部署 | 日常应用发布只更新集成代码；不要未经要求重建观测存储 |

## 分阶段能力检查

1. **干净运行**：从空 checkout 安装锁定依赖；清除“本机已有”假设，确认前端产物、编译器、解析工具、浏览器和本地数据库夹具。
2. **Runner 适配**：service 的 hostname、entrypoint、IPC、架构和资源按实际 executor 验证；先看服务端退出日志，再决定是否调整连接等待。
3. **通道**：连接建立、认证、TLS和正文计时分开；传输公开合成数据，至少测小响应和接近真实静态文件体积的完整 hash。
4. **无副作用发布演练**：计划模式、固定构建规则、非 root 可读、中断清理、部署身份允许／拒绝、基线身份匹配。
5. **快速故障合同**：真实子进程连接父服务、正常 EOF、背压、错误证书、损坏、超时、取消、确认丢失、更新发布竞争；不要仅 mock 一个成功字符串。
6. **冻结候选**：记录来源、候选 hash、实际线上版本和并行交付；必要时旧→新兼容，不能仅抄基线。
7. **正式检查与发布**：保留完整回归、不可变镜像、串行更新和同锁验收。
8. **独立核对**：用户访问路径、文件 hash、业务只读行为；前后 Secret／预算等关键约束只保存脱敏汇总，不能泄露其值。

这是有条件的路线，不要求每个纯文档改动跑八道门；已有证据适用且版本未变可复用并注明来源。

## 变量与配置的分层

生成运维表时至少区分下列来源；“变量名存在”不证明哪个值最终生效。

| 来源 | 建议记录 | 常见误区 |
| --- | --- | --- |
| CI 项目／组织变量 | 名称、脱敏值、类型、scope、保护、来源 | File 值应是正文，作业内获得临时路径；不是填操作者电脑路径 |
| 流水线默认值 | 默认、覆盖关系、消费者 | 源码关闭而项目变量开启，不能仅看 YAML 说服务未启用 |
| 作业生成变量 | 生成者、生命周期、清理 | 不把短期 Token 或 fixture 路径重复设成长期变量 |
| 可信发布主机 | 固定目标、受控脚本版本、身份和密钥到期 | 改仓库源码不会自动更新私有安装副本 |
| 应用配置／Secret | 归属、配置入口、重载方式 | 镜像发布不一定应用 Secret／副本／路由改动 |
| 基础设施 | 集群、调度、入口、证书、白名单、网络 | 更换 URL/context 不等于重建相应资源 |

不要在用户要求对照表时读取或展示秘密正文。目标 Pod 通常由 Deployment 创建，落点由调度决定；讲清“更新哪个容器”“副本数在哪配置”“实际落在哪个 Node”三层，不把自动生成 Pod 名作为长期部署目标。

## 范围与可验证输出

CI 失败只允许诊断时，输出证据和最小改动方案；用户要求实现且授权充分则完成相关实现和验证。受保护分支／provider限制是项目配置，不全局强制某个分支名、某个供应商或固定预算。

计划应具体到文件、身份、网络跳点和验收，不承诺未验证的部署能力。涉及新权限或费用的必要缺口用精确动作和限制说明，已授权的独立工作继续完成。
