# 验收与副作用对账

## 状态必须按目标记录

| 状态 | 最低所需证据 | 下一步选择 |
| --- | --- | --- |
| 未开始 | 前置失败且无派发证据，或可信服务端明确not_started | 修前置条件，再按既有幂等规则执行 |
| 派发未确认 | 有原request，无确定完成/未执行收据 | 保留原身份，对账，不清unknown、不另建身份盲重试 |
| 部分应用 | 每个目标实际版本、UID、配置、generation与时间窗 | 判断兼容和归属，选择受控继续或回退 |
| 已应用未验收 | 更新证据完整，入口／行为／完整性检查未过或未跑 | 单独排查验收路径，不称未部署或验收通过 |
| 验收通过 | 候选与目标一致，所有约定检查在对应窗口完成 | 记录范围和限制；不外推未测HA或收费业务 |

只有部署命令返回失败、连接超时、job红色，无法判定外部动作未发生。原请求查询、实际目标读回和变更前快照优先；证据可能过期或属于不同候选时明确未知。

## 建议证据字段

最小记录按任务取用，不为小改动制造固定表单：

```text
release_identity / commit / pipeline / candidate_digest
phase / original_request_id / target_uid / observed_version
started_at / observed_at / generation / readiness
bytes_expected / bytes_received / sha256 / elapsed_ms
exit_code / signal / applied_state / confirmation_state
evidence_path / unresolved / cleanup_owned_resources
```

这些是结构名，不是要求采集敏感用户内容。保存hash不等于允许输出原Secret；有哈希也不能替代真实归属／兼容证据。

## 验收分层

- **格式／计划**：YAML、本地规则和计划模式；不等于服务端接受或可以部署。
- **合同／隔离**：fake控制面、loopback、真实本地PG、合成提供方；明确模拟边界。
- **完整回归**：同一候选所有必要测试；定向15/15不等于原全量全部通过。
- **实际发布**：可信不可变产物、来源、真实目标、就绪／digest核对。
- **用户路径**：真实入口TLS、路由、鉴权和完整文件；窗口及来源分别记录。
- **真实业务／HA／回退**：单独约定并授权，不能从CI通过推断。readiness503不等于用户错误，页面200也不证明任务成功。

## 回退与幂等

回退前确认前版产物可用、schema和状态兼容、当前目标仍属本次发布且没有更新版本。对UID/resourceVersion或等效版本做条件更新；有竞争或归属未知即停在未确认，不覆盖他人新发布。

复验同一身份不会自动授权重放写入：先查项目脚本如何处理已应用镜像、pending／receipt，再决定是否继续。部分目标已更新时，恢复描述保留原事实，不把后续成功写成第一次无副作用。

## 远程验收位置变更

仅在原路径限制有证据且用户范围允许时采用。固定可信验证器至少约束目标origin、方法、路径、响应大小、阶段时限、TLS与来源；绑定候选、清单和验证器版本；拒绝任意URL、上传程序、认证头和不匹配摘要。条件允许再用独立用户来源对照。

发布依赖故障与业务依赖故障要分开；不要为减少发布失败把跳板加入业务流量路径。

## 停止与清理

暂停既有任务时查看正在运行job、自动合并、开关和派发各自状态，不只关闭本机进程；保留业务资源和原账本。清理仅操作记录归属的临时目录、子进程、镜像、端口和Key，不追随凭据软链接删除原件。

有效凭据轮换需同步两端身份、scope、固定命令和到期时间，不把临时新权限永久化。用户授权额外费用时将其落实为具体次数／额度／有效期后才执行；没有明确费用边界不继承历史预算百分比。
