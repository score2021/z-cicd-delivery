# 失败模式与最小区分实验

下列是通用诊断规则和合成情形；不是待执行命令，也不是对某个云厂商的根因断言。

| 症状 | 首次处理容易遗漏什么 | 最小区分实验 | 有证据后的修复方向 |
| --- | --- | --- | --- |
| 干净 checkout 测试失败，本机成功 | 未提交 dist、真实账本、预装工具或旧缓存 | 空目录安装；列失败文件依赖；用合成历史和独立 schema | 把构建顺序、fixture路径、工具安装写入作业；不复制真实账本 |
| 浏览器等控件超时 | 弹窗遮挡、details未展开、测试资源文件名不匹配 | 读实际DOM与fixture路径，执行真实可见操作 | 关闭弹窗、展开控件、注入本轮路径；不 force 点击或删除断言 |
| PG连接拒绝 | host不匹配、entrypoint没执行或服务已经崩溃 | executor版本、容器状态、init日志与SELECT1分开 | 按executor适配别名/localhost及初始化；崩溃不能靠加等待 |
| initdb退出异常 | IPC、共享内存、资源或镜像架构问题 | 最小PG初始化；一次只改一个因素，或明确组合实验 | 有限环境适配，记录未证明的因果，不改业务PG顶替fixture |
| SSH ENETUNREACH | 路由问题被误判密码问题 | DNS／IPv4IPv6／TCP banner分层 | 选择获准可达路径；不先索取高权限密钥 |
| HTTPS转发不经过loopback | IP literal不会走DNS lookup钩子 | 用合成IP／DNS目标分开检查TCP目的地与原SAN | 保留原Host／SNI与原目标SAN校验；不能关闭TLS |
| 错误证书负测只在第二次请求异常通过 | 连接池跨不同逻辑目标复用原握手 | 合法目标→错误目标交叉测试 | 修正连接池隔离；必要时局部禁用复用，而非全局关校验 |
| 子进程一直等父进程网络服务 | 同步exec阻塞父事件循环 | 真实子进程访问父进程小服务 | 使用异步子进程；fake命令成功不覆盖该死锁 |
| HTTP200／子进程exit0但hash不符 | stdout/socket仍有未交付缓冲 | 记录Content-Length、实收、EOF、exit/close顺序和背压 | 正常路径排空后结束，取消／异常才销毁；补慢消费者回归 |
| 小响应正常，大文件超时 | 认证、响应头、正文共用一种限时 | 分阶段计时；相同小/大文件经两条来源下载核hash | 按阶段有界配置；若一直缺尾，调查路径，不无限加总时限 |
| 部署已就绪但rollout watch超时 | 确认通道丢信息，不等于patch失败 | 新GET核generation、副本、UID、digest和来源 | 同一总预算内有界轮询；不扩大发布权限或重建目标 |
| 同样是SSH摘要失败 | 认证、上传、构建或push阶段混为一谈 | 脱敏phase、bytes、exit与远端原request收据 | 按阶段修复；先确认副作用再决定重试 |
| 端口在监听但集群不可达 | 陈旧隧道只剩listener | 核对所属PID命令和端到端只读请求 | 只恢复本项目通道；禁止全局杀SSH |
| CI旧候选覆盖较新上线 | MR通过后目标已被其他工作更新 | 部署前比对线上digest、来源与候选清单 | 取消过期发布并纳入已交付变更；不更新baseline放行旧版本 |
| 非root镜像无法读应用文件 | 安全解包把公开产物也设成owner-only | 在实际运行UID下读取打包文件 | 外层私有目录与镜像公开文件分层权限；不能扩大凭据文件权限 |
| 中断后残留认证材料 | 只测正常finally，未覆盖signal | 对自己的合成进程发中断并检查临时目录 | 生命周期受控清理，原凭据不动，避免全局清目录 |
| 后台事件数在越权测试中变化 | 数据pending先于对外语义事件完成 | 等同一input/call对应公开事件，排除正常提交 | 修取样同步，保留越权拒绝和副作用不变的原断言 |
| 旧owner恢复后没打预期日志 | 已先被存储fence拒绝，续租timer已关闭 | 核事实、epoch、唯一完成，不只看一行日志 | 接受有依据的停止路径；不放宽旧owner不得提交的约束 |
| 初始化期间丢租约 | 定时器在初始化完成后才开始 | 可控延迟覆盖取得租约到就绪窗口 | 从取得租约开始续租，失败清理原owner/epoch，各步复核fence |
| 提前续租后仍间歇过期 | DB行锁前计算时钟／有效性 | 可控锁等待，测获取、续租、到期不得复活 | 先锁行再采权威时钟；保留owner/epoch；不能改TTL掩盖 |
| 短deadline变TransportError | 时间单位向下取整、嵌套预算或退避截断 | 边界预算＋Retry-After；分别统计GET与写请求 | 一致预算语义和舍入；不重发非幂等写入、不删deadline断言 |
| readyz503但页面/API成功 | 排空摘流与业务可用性混淆 | 按用户路径／readiness分别统计窗口 | 保留各分母和原因，不能用任一指标替代全链路HA |
| 某来源访问观测平台超时 | 来源白名单，不一定服务宕机 | 来源策略与主机内只读health对照 | 修获准访问路径，不重启或公开服务以凑探测 |
| JUnit看不到 | 报告制品与普通archive读取方式不同 | 检查上传类型、报告API和原job结果 | 通过正确接口归档，区分未生成／未上传／读取方式错误 |

## 假设纪律

把每次尝试记为：现象 → 假设 → 仅改变的条件 → 实际结果 → 支持／不支持／不能区分 → 下一步。A/B不改善不等于证明该因素绝无影响，只说明当前实验不支持它是充分解释。

仅当有证据关联某版本或实现时才命名为根因。远端验证可缓解大响应路径问题，但应记录位置变化、验证完整性和新增发布依赖，不把缓解改写成原网络恢复。
